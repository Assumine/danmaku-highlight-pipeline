# 限制

## 不是通用语义模型

算法主要依赖群体行为、关键词和表情，不理解完整游戏状态。实际模式开始时无人提到模式名称，就可能漏检；观众长时间提前讨论某个模式，也可能形成误报。

## 弹幕不是实时真值

观众会延迟发送、复读、补充解释或讨论上一局。弹幕热度适合发现“大家在反应什么”，不等于画面中的节目效果仍在继续。结尾因此采用首次稳定回落，而不是最后一条相关弹幕。

## 多平台对齐依赖时间戳

绝对时间映射要求录制端和旁路采集端的时间戳可信。系统没有估计每位观众的网络延迟，也不能修复设备时钟严重漂移。

## 低弹幕场次效果差

用户数和持续时间阈值用于防止单人刷屏，代价是小直播间或深夜低活跃阶段更容易漏检。降低阈值前应先建立人工标注集。

## 语音边界会出错

Whisper 可能漏掉低声、重叠语音、游戏音效中的讲话或方言。语音边界只做有限范围的微调，不能判断内容是否值得保留。

## 外部依赖

- biliup：生产环境的录制和投稿工具，不随本仓库分发。
- FFmpeg/ffprobe：音视频切分、合成和完整性检查。
- faster-whisper：可选语音转写。

外部工具升级可能改变文件格式、时间戳或编码行为，应在升级后重新跑真实样本。

## 隐私与合规

弹幕 XML 可能包含 UID、昵称、文本和时间戳。公开数据集前应匿名化，并确认直播内容、弹幕数据、模型和平台操作符合授权与服务条款。
